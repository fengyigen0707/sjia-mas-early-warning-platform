# RareGuard 工程补齐与试点交接（2026-10-10）

本轮基于 `master` 的 `a6d5607397249823b4761fb87a54af5e69a3a794`。这是工程改造与验证准备，不是临床效果验证。默认规则档、数值阈值和评分权重保持原样。

## 本轮已补齐

- 家庭账号凭证、八小时 HttpOnly/SameSite 会话、退出撤销、登录失败限流。
- 新档案绑定账号，其他账号不能读取、写入、导出或删除。已有无归属档案不会被新账号自动认领；部署采用新试点库，旧记录迁移需要授权归属清单及运营离线迁移。
- 正常服务入口无账号配置拒绝启动；未认证演示必须显式声明合成数据离线模式；默认监听本机。
- 化验图格式/大小检查、云端识别逐次授权、所有试点识别结果核对后手工入库。双解析一致不再等于已人工确认。
- 档案导出/删除；敏感响应禁止缓存；就诊摘要和模型文案转义，防止脚本注入。
- 日期、数值、档位和趋势查询范围校验；非标准单位确认不重复换算；手工参考区间按相同单位换算；零基数不作比值趋势计算，绝对阈值规则仍保留。
- 真实 OCR 验收增加 `--require-real`：缺样例/密钥退出码2，缺标注/模型错误/准确率不达标退出码1，不能以跳过冒充验收成功。

## 有认证的本机联调

```bash
python scripts/create_family_account.py family01
RAREGUARD_ACCOUNTS_FILE=data/private/accounts.json RAREGUARD_COOKIE_SECURE=0 RAREGUARD_OFFLINE=1 python -m rareguard.api.home_server
```

凭证只在运营本机终端输出一次，通过私密渠道给对应家庭。配置文件只存SHA-256摘要，生成权限600。账号配置重启生效；重启会令全部会话失效。`COOKIE_SECURE=0`仅允许本机HTTP联调。操作员不得在公开截图、日志或仓库展示凭证。

页面先登录，再建档；出生日期由家长填写，已移除原来固定出生日期的占位。API脚本可用 `Authorization: Bearer <家庭凭证>`。凭证不进入浏览器持久存储。

## 小范围试点部署要求

1. 使用HTTPS反向代理；默认Secure Cookie；代理转发正确的外部Host和HTTPS协议。使用单Uvicorn worker（会话/登录限流当前驻进程内）。
2. 服务绑定本机并由反向代理暴露，限制可信Host、请求体8MB上限和边缘限流；不直接把开发服务暴露公网。
3. 新建空试点数据库；每个家庭发不同凭证。老档案不能通过猜编号认领。撤销账号需删除配置并重启；停用Bearer凭证与会话一起生效。
4. 文件/数据库使用专用系统账号和最小文件权限；按运营制定的加密备份、留存和销毁制度执行。数据库删除是活动记录删除，不是磁盘安全擦除；备份和追加审计须按授权留存政策处理。
5. 获取监护人明确授权。云OCR授权不能证明图片已经脱敏，部署方需要人工检查姓名、条码、医院号等信息；不愿上云时使用手工录入。
6. 当前家庭端写入没有完整合规访问审计，本轮不宣称已完成医疗合规上线。多机构、SSO、持久化会话/限流、完善访问审计属于下一阶段。

## 真实OCR验收（需要授权样例）

真实文件只进本地 `data/real_samples/`，不要入Git。每张PNG配同名JSON人工标注，建议用无身份含义的文件名。标注列表的每项至少包含 `code`或`name`、`value`、`unit`、`ref_low`、`ref_high`。数值为规范单位归一化后的值，`unit`字段沿用OCR原始单位契约；不要直接把原始mg/dL数值标成规范值。由两人对照原单复核真值，避免评测标签本身出错。

```bash
python -m evals.real_ocr_eval data/real_samples --require-real --output data/private/ocr-report.json
```

只有完整覆盖全部输入样例且字段加权准确率≥95%才通过。报告标明“真实OCR验证，不是临床验证”；准确率只是这批样例的结果，不能推广到所有医院/所有患儿。

## 医生与患者共创交接

| 任务 | 输入 | 验收产物 |
|---|---|---|
| 规则逐条评审 | `analysis/rules.py`、`trends.py`、`mas.py`、`docs/references.md` | 规则ID、适用人群、单位、依据、同意/修改、评审人和日期 |
| 简化评分评审 | 当前自定义八项评分，与正式MS公式区分 | 不以“HLH确诊”或“MS已实现”包装自定义评分；缺项处理及默认档建议 |
| 家长可用性走查 | 建档→打卡→OCR核对→预警→就诊摘要 | 实际参与人数、困难点、修改建议、授权与反馈记录 |
| 临床验证方案 | 经审批、脱敏、标注的回顾性数据 | 独立标签、样本量依据、划分、防泄漏方案、置信区间、误报/漏报报告 |
| 真实家庭试点 | 医生复核与授权、隐私流程、退出机制 | 分期试点记录及问题清单；未完成前不上临床有效性结论 |

MS公式、LDH/查体变量、权重配置和官方动态幅度分级仍维持原需求清单的延期状态；不在缺少医生评审时自动添加或更改医疗判险。
